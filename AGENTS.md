# Тексты интерфейса

Новые надписи и сообщения, которые видит пользователь в приложении, должны быть на английском языке.

# Дизайн

Макеты приложения в Figma: [TaskB](https://www.figma.com/design/JCuXmqS3cx8qqwB0eY6MFb/TaskB?node-id=0-1).

# Цвета интерфейса

Используйте цвета из общей палитры `Palette` в модуле `ui`.
В теме задавайте семантические цвета через `Palette`, а в компонентах и экранах
используйте `TaskBTheme.colors`. Для выбора конкретного цвета, например цвета группы,
обращайтесь к `Palette` напрямую.
Не задавайте произвольные HEX/RGB-значения цветов в теме, экранах и компонентах.

# Иконки интерфейса

Используйте готовые иконки из подключённой библиотеки Material Symbols
(`com.composables.icons.materialsymbols`) через общий объект `TaskBIcons` в модуле `ui`.
Если нужной иконки нет в `TaskBIcons`, добавьте туда ссылку на иконку из библиотеки.
Не создавайте собственные SVG/PNG, векторные пути или рисунки на Canvas для иконок интерфейса.

# Экраны фич

Каждый экран фичи размещается в папке `screen/<screen_name>/` вместе со своим Store,
состоянием, Intent, reducer и другими классами, относящимися к этому экрану.
Не создавайте папки `mvi` на уровне фичи.
Для тестов конкретного экрана используйте такую же структуру папок.
Общий для нескольких экранов код размещайте вне папок отдельных экранов.

# Файлы MVI для экранов

Для каждого экрана размещайте объявления MVI в отдельных файлах внутри папки экрана:

- `<Screen>State.kt` — состояние экрана, его вычисляемые свойства и связанные с состоянием
  модели, например типы диалогов. Модели диалогов оставляйте в файле состояния.
- `<Screen>Intent.kt` — тип Intent экрана и его варианты.
- `<Screen>Reducer.kt` — тип Message экрана и его варианты вместе с функцией `reduce<Screen>`.
- `<Screen>Store.kt` — реализация Store. Не объявляйте State, Intent, Message или reducer
  в этом же файле.

# Имена интерфейсов и реализаций

Интерфейсы, задающие контракт поведения, называйте с префиксом `I`, например
`IGroupRepository`, `IAppSettings`, `IStore`, `IGroupDao`.
Классы реализаций называйте без префикса `I`. Основная реализация `IGroupRepository`
должна называться `GroupRepository`, без указания технологии хранения в имени.
Имя файла должно совпадать с именем объявленного в нём интерфейса или класса.
Для типов, описывающих варианты данных (`Intent`, `Message`, `Dialog`, маршруты),
префикс `I` не используется.
